Plugin model

Extensions should explain their blast radius.

Traditional plugin systems ask users to trust unknown code. Zayvora plugins declare what they can touch, what they require, and whether their effects can be replayed.

01 / declare

Plugin

Defines purpose, inputs, outputs, mutation scope, and required authority.

02 / verify

Validator

Checks contracts before execution and rejects unsupported guarantees.

03 / bind

Continuity Contract

Signs the operational promise that makes replay and audit possible.

04 / run

Safe Execution

Executes under scoped authority with lineage attached to state changes.

Contract fields

  • →Mutation scope: what the plugin can change.
  • →Replay compatibility: whether effects can be re-run.
  • →Authority requirements: who can invoke it.
  • →State guarantees: what must be preserved.
  • →Version boundary: which runtime contract applies.
